# Release 7.3.9

> **Status:** Stub — not yet drafted.

## Summary

The "PDF engine + period-drift" release. Two big internal changes that are
mostly invisible to end users:

1. **TCPDF removed.** Sole PDF engine is now `setasign/tfpdf` (canonical UTF-8 fork of FPDF, same maintainer as FPDI). Barcodes via `picqer/php-barcode-generator`. Net: ~25MB smaller per install. New in-tree HTML shim for simple `<b>/<i>/<u>/<br>/<font color>` in PhreeForm table cells.
2. **`journal_main.period` self-heal.** New `repairJournalMainPeriod()` runs once on upgrade, re-stamping period from `post_date` against `journal_periods`. Fixes years of accumulated drift from quality tickets, work orders, and future-dated recurs.

## What to cover when this gets drafted

- Composer changes: `tecnickcom/tcpdf` removed; `setasign/tfpdf ^1.33` + `picqer/php-barcode-generator ^3.0` added; `setasign/fpdi_pdf-parser` moved from `require` to `suggest`
- The new `calculatePeriod()` auto-extend behavior (`ensureFiscalYearCovers`)
- `fyClose` now ends with a JOIN-based re-stamp pass (self-heals drift on every future close)
- `bizCacheExpClear` admin button (Settings → Bizuno → Tools → Clear Business Cache)
- Cross-module `lang()` fallback so module-owned keys translate via `viewKeyDropdown` without callers naming the module
- Role-security parent-from-max-child bridge (`removeOrphanMenus`) so `inventory/build/manager` is reachable
- Migration off `getModuleCache('bizuno', 'options', ...)` to `getMetaCommon('options_*')` across 13 callers
- New `bizScrubSensitive()` helper redacts pass/pwd/token/card/cvv in debug output
- CSRF Layer 2 default-on (`BIZUNO_CSRF_ENFORCE = true`)
- Tickets manager fixes: period default restored, status/closed filter wiring repaired, `creation_date` column added

## Action required

- Run `composer update` after pulling
- Manual: drop `setasign/fpdi_pdf-parser` re-require if you have a Setasign license and want modern-PDF support (see [README › Optional commercial parser](../../../README.md))
